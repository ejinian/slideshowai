## Domain — slidelabs.ai (custom), Vercel underneath

**The product is `SlideLabsAI`, domain `slidelabs.ai`.** Renamed from "SlideShowAI" on 2026-07-23 (all user-facing text, titles, legal, onboarding, the Logo, package name, localStorage keys, and the E2E test-user email). Vercel serves it; `slideshowai-three.vercel.app` is still the underlying deployment host (a project/infra name, NOT rebranded — a real custom-domain cutover of the vercel URL, `NEXT_PUBLIC_APP_URL`, `app/sitemap.ts` BASE, the cron pinger, and TikTok domain verification is separate work). The public contact email is still `slideshowai@gmail.com` (a real inbox — left untouched until a SlideLabs inbox exists).

**OAuth redirect gotcha (hit 2026-07-22):** after Google signup a user landed back on the `*.vercel.app` URL instead of `slidelabs.ai`. Cause is **Supabase Auth config, not code** — the app is domain-agnostic (`GoogleButton` uses `window.location.origin`, `app/auth/callback` trusts `x-forwarded-host`). Supabase only honors the app's `redirectTo` if it's in the **Redirect URLs** allow-list; otherwise it silently falls back to the **Site URL**. Fix in **Supabase → Authentication → URL Configuration**: Site URL = `https://slidelabs.ai`, and add `https://slidelabs.ai/**` to Redirect URLs (keep the vercel URL + `http://localhost:3000/**`). Google Cloud Console is unaffected — Google redirects to Supabase's callback (`https://eppgkfwhcciutepccveo.supabase.co/auth/v1/callback`), never the app domain.

**Custom-domain cutover is DONE (2026-08-08).** `NEXT_PUBLIC_APP_URL` = `https://www.slidelabs.ai` (TikTok OAuth + image proxy), and `app/sitemap.ts` BASE reads that env var — the `slideshowai-three.vercel.app` string in it is only a fallback for when the var is unset, not a hardcoded URL. Signature files for TikTok URL-prefix domain verification are served for **both** `slidelabs.ai` and `www.slidelabs.ai` (`public/tiktok*.txt`).

⚠️ **Both hosts must stay registered everywhere**, because `tiktokRedirectUri()` derives `redirect_uri` from the *browsing* origin (`x-forwarded-host`), not from an env var — so a user on the bare domain sends a different `redirect_uri` than one on www, and TikTok rejects any that isn't in the app's allow-list. Belt and braces: Vercel redirects `slidelabs.ai` → `www.slidelabs.ai`, and both callback URLs are registered under Login Kit.

## Design Philosophy — Lovable-Style Hyper-Frictionless UI

The dashboard is modeled almost entirely on [Lovable.dev](https://lovable.dev)'s design language. When making any UI decision, ask: "Would this feel at home on Lovable?" If not, don't ship it.

**Core principles:**
- **Zero friction above all else.** Every extra click, modal, border, or label is a failure. Remove it.
- **Black background (#000000) everywhere.** Not dark-gray, not navy — pure black. Cards are `#1c1c1e` (iOS system background). No gradients on cards.
- **Full-page hero gradient** sits behind everything including the navbar — lives on the layout wrapper, not the page. Class: `bg-hero-glow` (blue/indigo/violet → pink via radial-gradients on pure black).
- **Transparent navbar** — no border, no backdrop-blur, no background. Just floats over the gradient.
- **Cards have no visible borders.** Use `bg-white/[0.02]` or `bg-[#1c1c1e]` for depth. `border border-white/[0.08]` max — almost invisible.
- **Custom dropdowns only** — never native OS `<select>`. Build with absolute-positioned panel, `useRef` + `mousedown` for click-outside. Panel: `bg-[#1a1a1c] rounded-xl border border-white/[0.08] shadow-2xl`.
- **Composer (2026-07-14, from the "Composer Redesign" Claude Design file, then simplified twice):** ONE seamless card with **no internal borders or boxes** — the textarea is flush/borderless (transparent, no inner box, no hairline dividers, no footer border), with the chat-style "Add photos" attachment strip directly under it (drag-drop works on the whole card; photos go to `/api/generate` as `userImages`, used for the first slides). Pill dropdowns in the top settings row (Slides / **Detail** / **Goal** — goal is appended to the model prompt; Layout was removed 2026-08-07, see the Detail-pill note below). **Niche was removed (2026-07-22)** — the server auto-detects it from the prompt (see the niche-detection note below), so there's one fewer decision and no niche↔prompt mismatch. **Source stopped being a dropdown (2026-07-26)** — "Source" is jargon and a dropdown for exactly two options was displaying state the attach strip already showed. It's now a one-click text toggle in the footer (`id="source-toggle"`, targeted by id in e2e so copy tweaks are free): "No photos? Use ours" ↔ "Using our photos · Use my own". No numbered steps or section headers. Accent `Generate ↑` pill in the footer (keep `aria-label="Generate"` in manual mode — e2e depends on it; it becomes "Let AI decide" in AI mode). The **"Let AI decide"** toggle hides the whole settings row — see the AI-decide section below.
- **No emojis** in the UI. Ever. (Exception: image collection cards use emoji visually in their gradient tiles, not as text labels.)
- **Typography:** text-white at full opacity for primary, `text-white/50` for secondary, `text-white/30` for placeholder. No colored text except the accent.
- **Accent color:** `#6366f1` (indigo-500). Used sparingly — only for active states and the logo.
- **rounded-2xl** for cards, `rounded-xl` for panels, `rounded-full` for pills and avatar.
- **Try suggestions** (3 max, collapsed so they never truncate) change dynamically based on the selected image collection. Source: `NICHE_SUGGESTIONS` in `lib/generator-options.ts`.
- **Options above textarea** — Slides, Detail, Goal dropdowns sit in an options bar above the text input inside the same card. No separate section. (Niche removed 2026-07-22.)

**What we explicitly removed:**
- Native `<select>` elements
- Any border/outline on the main form card
- The standalone "Generate Slideshow" button
- Emojis from labels and suggestions
- The navbar border/line
- `overflow-hidden` on the generator card (breaks dropdown panels)

## TikTok Content Posting API — LIVE (end-to-end working as of 2026-07-03)

Full flow works: OAuth connect → init → TikTok pulls proxied JPEGs → status poll → `PUBLISH_COMPLETE` → private post lands on the target user's profile. Posts persist to `tiktok_posts` and render in **My Posts** (`/dashboard/posts`).

**API:**
- Init: `POST .../v2/post/publish/content/init/` — `DIRECT_POST`, `media_type: PHOTO`, `source: PULL_FROM_URL` (no binary upload).
- OAuth: authorize `https://www.tiktok.com/v2/auth/authorize/`, exchange + refresh `.../v2/oauth/token/`. Scope `video.publish` (works for photos). Access token 24h; refresh token 365d rolling. Client key/secret never `NEXT_PUBLIC_`.
- Status: `POST .../v2/post/publish/status/fetch/` with `publish_id` → `PROCESSING_DOWNLOAD` | `PUBLISH_COMPLETE` | `FAILED`.
- **Token endpoint responses are FLAT** (top-level `access_token`/`refresh_token`/`open_id`; errors as `{error, error_description}` strings) for BOTH exchange AND refresh — NOT nested under `data`. (Content-posting endpoints DO nest under `data` with `{error:{code,message}}`.) Reading `.data` on token responses is the recurring bug — it hit both the callback and `getValidToken`.
- Rate limits: 6 init/min per user; max 5 pending posts / 24h.

## Slide rendering — text is NEVER baked into storage (on-demand compositing)

Captions are live data (`slides.caption` + `position_x/y`, `align`, `max_width`); stored images are the **text-free background only** (`{i}-bg.jpg`). Text is composited on demand — never saved into the image — so everything stays editable until post.

- **Shared renderer**: `lib/generate/renderSlide.ts` (`renderSlideJpeg`) = clean bg + DB text → JPEG. The ONLY place text gets baked.
- **Where it runs**: in-app display `app/api/slideshows/[id]/render/[pos]` (session-authed), the TikTok pull proxy `app/api/tiktok/img/[id]/[pos]` (HMAC), and the `.zip` download. Hub thumbnails / PostViewer / Generator filmstrip all point at the render endpoint.
- **Reposition is a pure DB write** (`app/api/slideshows/[id]/reposition`) — no Sharp, so caption stacking is structurally impossible. (The old bug: reposition re-baked onto the already-baked image because a `.replace(/\.png$/,'-bg.jpg')` regex no-op'd on `.jpg` paths.) The same route now also accepts an optional per-slide `caption` (trimmed, ≤300 chars, empty ignored) and touches the parent `slideshows.updated_at` after every save.
- **A newline in a caption is a HARD break (2026-08-07).** `wrapText` used to split on `/\s+/` across the whole string, flattening every author line break into a space — a stacked list baked as one run-on sentence ("fix google maps today upload the front door menu board best drink…"). Invisible while the copy model only wrote single-line captions; it appeared the instant one wrote stacked ones, which is the format real viral decks actually use (every deck in `viralExamples.ts` is stacked). Wrapping now runs per segment, so **a caption with no newline is byte-identical to before** and no stored deck re-flows (regression-checked across the shipped corpus × 7 width budgets: 0 drift). Blank lines are collapsed, not emitted: an empty entry would render as a gap in the resvg bake but collapse to nothing in the editor's per-line `<div>`, breaking WYSIWYG, and would draw a stray pill in `plateSvg`. One fix covers both surfaces because `SlideEditor` renders the same `layout.lines`.
- **Captions NEVER truncate (2026-07-24).** `layoutSlide` shrink-to-fits: if text overflows the role's line budget at base font size, the font steps down (×0.92, floor 0.55×) until it fits — and past the floor it just renders every line. `wrapText` no longer takes maxLines or emits "…" (an ellipsis on a slide is a hard product failure; Ernest's rule: a genuinely viral caption ALWAYS beats brevity). Short captions lay out byte-identical to before, so existing decks don't shift.
- **Caption text is editable in-app (2026-07-24).** `SlideEditor` has a Caption textarea (live WYSIWYG, debounced save on the reposition route, empty reverts on blur; numbering note for reason slides). Covers BOTH the just-generated `/dashboard` view and the detail view (same component). Generator syncs its result state via `onSlidesChange`; `SlideshowDetail` fires `router.refresh()` after every save — that purges Next's client router cache, so "← Back to slideshows" re-renders the hub fresh (back/forward nav otherwise serves the cached payload regardless of staleTimes). Hub thumbnails are versioned `?v=<updated_at>` to bust the image cache.
- **Fonts on Vercel**: sharp's librsvg **ignores embedded `@font-face` on Linux** (tofu glyphs, though fine on macOS). So text is rendered with **`@resvg/resvg-js`** (`fontFiles` = the caption TTFs in `assets/fonts/`), which is deterministic cross-platform. Requires `outputFileTracingIncludes: {"**": ["./assets/fonts/**/*"]}` + `serverExternalPackages: ["@resvg/resvg-js","sharp"]` in `next.config.ts`.
- **Caption font = TikTok Sans** (`TikTokSans-700/800.ttf` = Bold / ExtraBold static weights from TikTok's own display family — the exact classic caption font; Montserrat/Inter were only approximations). resvg matches `font-family: "TikTok Sans"` + `font-weight` 700/800 to the right file (the 800 file's RIBBI family is `TikTok Sans ExtraBold`, but its typographic family — name-table ID 16 — is `TikTok Sans`, which resvg honors). `lib/generate/fonts.ts` (`CAPTION_FAMILY`, `captionFontFiles`) feeds the resvg bake; the editor overlay (`CaptionLayer`) uses `var(--font-caption)` loaded via `next/font/local` in `app/layout.tsx` — same family both places = WYSIWYG.
- **No decorations, classic TikTok captions only (2026-07-10)** — the purple accent elements (title rule, CTA pill, number badge) were removed everywhere. Slides are white TikTok Sans text with a **black outline** and no scrim (the classic TikTok caption look, added 2026-07-17): the bake uses SVG `paint-order="stroke"` + `stroke-width ≈ 0.15·fontSize` (resvg honors paint-order, so the stroke sits behind the fill and letters keep their weight); the editor overlay mirrors it with `-webkit-text-stroke` + `paint-order: stroke`. The old radial scrim was removed from both — the outline does the legibility work. Numbered slides carry the number INLINE in the caption ("1. …", added by `layoutSlide` unless already numbered). Default caption `y` = **0.58** (upper-middle) so it clears TikTok's bottom UI chrome.
- **WHAT THE USER TYPES IN THE CAPTION BOX IS WHAT RENDERS — no exceptions (2026-08-08).** `layoutSlide` auto-prefixes `"2. "` onto reason/plug slides whose text isn't already numbered. That was written 2026-07-13, before captions were editable; once in-app editing shipped (2026-07-24) it became an **override of the user's own text** — delete the number in the box and the next render puts it back, so the field and the slide disagreed with no way to win. Fix: **editing a caption clears `slides.number`** (in `reposition/route.ts`, mirrored optimistically in `SlideEditor.setCaption` so the overlay obeys on the same keystroke). Untouched slides still auto-number; a number the user typed themselves is kept verbatim; `reorder` doesn't reassign `number`, so the fix survives a reorder. **The general rule this is an instance of: any auto-formatting of caption text — numbering, capitalization, punctuation, emoji-stripping, trimming — may run at GENERATION time only. Never at render time over a field a human can edit.** Render-time rewriting is unwinnable by the user and invisible in the box.
- Generation auto-saves slideshows (`status:'saved'`) — no manual "Save to library" button.
- **Background library**: ~355 Pexels photos per collection in the public `library` bucket + `library_images` table (migration 20260707140000; metadata `alt/query/source_w/source_h/avg_color` added by `20260714100000_library_image_meta.sql`). Ingest / top-up / backfill: `node scripts/ingest-library.mjs [--collections=a,b] [--backfill-meta]` (needs `PEXELS_API_KEY`; resumable, paced under Pexels' 200/hr). Only `ecommerce` is empty; every other collection has ~355 rows. **The library is now just the FALLBACK** for stock backgrounds — real image selection is the live Pexels pipeline in the generation section below. (`lib/generate/backgrounds.ts` random sampling was replaced by `imageSelection.ts`.)

## WHY POSTS GO VIRAL — the model everything else serves (2026-07-26)

**A slideshow spreads for exactly one of three reasons. A post that is none of them is invisible, no matter how clean the writing is.**

1. **Humour** — it is genuinely funny.
2. **Value** — someone finishes it knowing something genuinely useful.
3. **Shock / lust** — it is startling, unhinged, or physically attention-grabbing.

**We build for VALUE.** Humour is parked (the banks still exist in `captionFrameworks.ts`, behind `TWO_SLIDE_COMEDY` / `THREE_SLIDE_COMEDY`, unused on purpose — re-enabling is a one-line change). Shock is deliberately out of scope: too much brand risk.

**The failure this exists to prevent:** decks that are *true, useless and forgettable*. Real examples we shipped — "focused core activation every session", "it takes a mix of nutrition and full-body workouts", "consistency is what matters". Nobody screenshots those. Compare a real viral deck on the same topic: "eat in a 600-800 cal deficit", "treadmill at 3 incline 15 speed", "do ab exercises 3-4x per week, not once".

**The test for every slide: could a stranger DO something differently after reading this?** If not, it's dead weight. A number, a frequency, a dose, a named thing, or a followable instruction is usually what separates the two — but **specificity is judgement, not a quota**. A slide making a mindset point can be fully concrete with no digits ("you are training abs like a warm-up, not like a muscle"). This is why there is no hard "must contain a digit" validator; `/api/generate` only *flags* a short deck where nothing is actionable, in diagnostics.

**Structurally, value needs two text blocks per slide** — a short heading and a `body` paragraph carrying the protocol. One caption per slide made value posts impossible to express. See the short-deck section below.

### Anti-AI-voice — the separate "sounds human" axis (ongoing, 2026-07-29)

Value/hooks is one axis; **voice authenticity** is a distinct one — a caption can be true, on-topic and grammatical yet obviously read as AI ("mocha blend adds a chocolatey twist, perfect for a creamy finish"). The **living design doc is [`docs/anti-ai-voice.md`](docs/anti-ai-voice.md)** — it holds the growing **tell taxonomy** (evaluative tail clauses, abstract sensory nouns, twee personification, over-balanced parallelism…) and the options being weighed. Current lean: **RAG real captions from our own trend pipeline into the judge** (positive examples beat more rules) + encode the taxonomy mechanically in `lib/generate/aiLingo.ts`. **AI-detector APIs are NOT a good per-caption judge input** (unreliable on short text, and a score isn't actionable) — only useful as a diagnostics metric. Keep the doc updated as we spot new tells.

## Slideshow generation — v2 (relevance-aware + trend-driven, 2026-07-16)

Two intake directions share one vision brain. Orchestrated in `app/api/generate/route.ts`.

**Copy** (`lib/generate/listicle.ts`, model `gpt-4o` — NOT gpt-4o-mini anymore):
- **The user's prompt is the TOPIC that drives the whole slideshow** (it used to be treated as a "product to plug on one slide" — that produced generic niche listicles for real topics). The product plug is now conditional (only if the topic names a product).
- **Trend-fed**: `lib/generate/trendExemplars.ts` reads the freshest high-velocity real hooks for the niche from `trending_posts` at runtime (niche-mapped by slug AND label; 5-min cache) and injects them as few-shot exemplars.
- **Niche is auto-detected, not chosen (2026-07-22).** The composer no longer has a Niche pill. `/api/generate` calls `resolveNiche(body.collection, body.prompt)` (`lib/generate/nicheDetect.ts`): an explicit slug from "Let AI decide" always wins, otherwise a fast keyword vote over the prompt picks one of the `GENERATOR_NICHES` slugs (else `"other"`). Niche is a **soft input** — it only steers trend-exemplar selection (a coarse 5-bucket taxonomy) and the aesthetic image "vibe" pool (`pinterestPool`) — so a wrong guess just means less-targeted trends, never a broken deck. This killed a whole bug class (niche said "Gym", prompt was about coffee → topic drift) and removed a decision. The frozen-library fallback maps `"other"`→`gym` (largest collection); everything else degrades gracefully.
- **THE PROMPT IS THE ONLY SUBJECT. Niche never reaches the copy when a topic exists (2026-07-31).** "Niche never decides the copy" was aspirational until this date, not enforced: `listicle.ts`, `imageFirst.ts` and `judge.ts` all printed `Niche: <label>` on the line **directly above** `TOPIC —`, which reads as a second subject and gets averaged with the first. Now the niche line is emitted **only when `req.description` is empty** (the one case where it's the sole signal); with a topic it is absent entirely and the prompt adds "That topic is the entire subject. Do not widen it, and do not blend in the creator's trade or any other industry." The judge got the mirror change so it stops scoring drift as on-brief. Verify by rendering `buildUser` directly — with a topic the string must contain no `Niche:`.
- **The onboarding profile must NEVER enter a creative prompt.** `/api/suggest` used to put `user_metadata` (`business_name`, `niche`, `goal`) into its brief JSON as `profile`. A landscaper typing "cool cars" got back three plans about luxury car **landscapes** — the model had two subjects and fused them. The profile block is gone, and the planner's system prompt now states outright that the subject is the direction + photos, the creator's trade is not the subject, and `niche` is a routing label only (prefer `"other"` over the nearest business-shaped match). What the creator *sells* is not what the post is *about*. **`app/api/trends/remix` is the deliberate exception** — "remix this trend for my business" is the whole feature there, so it keeps reading the profile.
- **Voice is hard-constrained**: no exclamation marks, no Title Case, no clichés ("you're probably making", "game-changer"). Viral-anatomy system prompt (slide 1 = pattern-interrupt hook).
- **Explicit list count is honored**: `explicitListCount()` reads "3 exercises" → 5-slide deck, so the headline number never contradicts the topic.
- Structured JSON, validated + retried: title (numbered hook) → reasons → one optional plug → cta. `image_keywords` per slide feed image sourcing.

**Images — user uploads = the PRIMARY flow, image-first** (`lib/generate/imageFirst.ts`): one `gpt-4o` vision call SEES the uploads, writes captions grounded in them, orders the most scroll-stopping on the hook slide, and **EXCLUDES** unrelated/low-quality photos (route returns an `excludedPhotos` count). `photoIndex = -1` slides fall through to stock fill. Falls back to copy-first + positional on any vision failure.

**Images — stock, LIVE Pexels sourcing** (the caption-accurate path; used when there are no uploads):
1. `lib/generate/liveImages.ts` — searches **Pexels at runtime** with each slide's keywords, then a **strict `gpt-4o` vision judge** picks the result that genuinely depicts the caption or returns **-1**. **Judging is TWO-PASS and strict since 2026-08-27** (Christian's 99% rule: if the image doesn't clearly match the text, redo it): the ranking call picks candidates (temperature 0), then `verifyPicks` audits each chosen image ALONE with a binary "does this clearly depict the caption" call — any "no" demotes the slide to -1 → the AI fill. The single big ranking call is provably noisy (same deck flipped between approve-all and reject-most run to run) and prompt strictness alone let equipment-only shots through (floor dumbbells approved for "go heavy on curls" — the complaint that triggered this); the isolated binary check is the mechanical backstop. Old leniency rules ("any bench press photo depicts leg-drive advice", "generic hooks: don't return -1") are GONE — hooks now need the deck's subject in action too, and a no-person photo can never match a caption about doing something. Verify fails open (all true) so a broken audit never degrades below old behavior. Pexels HAS the specific movements the frozen library lacked (verified: "incline dumbbell press", "bench press" return exact matches) — runtime search fixes the root cause for ANY topic. `-1` slides take the best Pexels result / a bundled local photo.
2. Falls back to the **frozen library** (`imageSelection.ts`: vision → LLM-text → keyword → random) only when `PEXELS_API_KEY` is absent.
3. **Deck variety is enforced two ways (2026-07-24):** the judge prompt bans text-bearing candidates and same-photoshoot repeats, AND a deterministic backstop in `selectLiveBackgrounds` caps any Pexels photographer at 2 slides/deck + bans exact URL repeats (covers judge picks AND `-1` fallbacks; swaps stay within the slide's own candidates, no-op when there are no repeats). Cause: Run 2 diagnostics had 4/6 slides from one dealership shoot — same models on slides 1/3/6.
4. **The Pinterest aesthetic pool is text-screened.** Pins with baked-in typography (title cards, doodle handwriting, watermarks, logo walls) collide with our captions and crop mid-word at 9:16, and **a prompt-only judge veto was proven insufficient** (the judge rubber-stamped the same truncated-text pin in two separate runs). `scripts/screen-pool-text.mjs` vision-scans the pool and flips flagged rows `source: 'pinterest' → 'pinterest_text'`, which drops them from `pinterestPool()` with zero app code (reversible; Storage untouched). 2026-07-24 sweep: **250 of 493 pins flagged** (~34% + a gpt-4o second pass — use `--model=gpt-4o`, mini misses doodle text). Re-run after any `ingest-pinterest.mjs` top-up.

**Detail pill replaced the Layout pill (2026-08-07, Ernest).** Layout was mockup data: `/api/suggest` picked a value, the route logged it and wrote `slideshows.layout`, and **no copy prompt ever read it**. Gone from the composer, the mobile sheet, the AI-decide chips and the planner schema; the nullable DB column is still written (`"listicle"`) so the row shape is stable. In its place `DETAIL_LEVELS` — **Short captions** (one line, default), **Long captions** (heading + two-part body), **Let AI decide**, **Both — compare**. `auto` picks ONE direction for the whole deck and applies it to every slide (per-slide deciding was tried and collapsed: handed an optional field the model filled 5 of 5, so it was just long with shorter bodies). `both` runs the copy twice — short then long — and returns TWO decks the user picks between; it reuses the existing `slideshowCount` machinery, so images, compositing, persistence and the results list needed no change. ⚠️ `compareMode` must resolve **before** `costOf()` — it forces `slideshowCount = 2`, or two decks bill as one credit and the persistence loop only sees one. **How many** decks is a SEPARATE control from the format: a `2 versions` footer switch (`#two-versions-toggle`) sends `slideshowCount: 2`, which reuses the existing variation machinery (`buildUser`'s `variant` param already tells run 2 to pick a different hook angle). It is **forced on and disabled** when Detail is `both` — two decks by definition, and showing it locked explains the 2-credit cost rather than surprising the user. Both + toggle is still 2 decks, never 4. **Results are one card with a segmented switch, not a stack**: only the active deck's `SlideEditor` mounts (each one loads every slide image), so there is one set of post/download buttons and one Regenerate — stacked, nothing said which deck the buttons acted on and both Regenerates rebuilt everything. Segments read `Short`/`Long` from the `variant` field in compare mode, `Option N` otherwise. ⚠️ `e2e/generator.spec.ts` drives the pill dropdowns BY LABEL — renaming or removing one breaks the suite and blocks `git push`. Sends `detail`, validated against `DETAIL_VALUES` server-side and falling back to `"short"`. ⚠️ Observed: `auto` gives most value slides a body rather than a genuine mix — it reads as a middle setting (one-line bodies, unnumbered headings), not a mixed deck. Tighten `AUTO_LISTICLE_BODY` if that matters.

**Long captions — heading + two-part body on a long deck (2026-08-07).** `detail: "long"` → `usesBody(count, detailed)` in `captionFrameworks.ts`, **the single gate** replacing `count <= SHORT_DECK_MAX` inlined at ~10 sites; a deck whose schema says `body` while its prompt says heading-only silently returns empty bodies, which is what drift there costs. Format is transcribed from a real 6-slide deck: numbered heading, then a body of TWO paragraphs split by a blank line — para 1 the unflattering *before* ("i was swallowing everything half-chewed like an animal"), para 2 the *after*, opening "now i…" and carrying a hard number. Default (off) decks are byte-identical: `normalize` still drops `body`, and the schema still omits it. ⚠️ **A blank line needs explicit content in BOTH renderers** — an empty `<div>` collapses to zero height AND an empty `<tspan>`'s `dy` is dropped (no glyph to advance past), so both emit `&#160;`/` `. Getting this wrong renders the two paragraphs flush and looks like the feature does nothing. ⚠️ `cleanCaption`'s three `\s{2,}` collapses ate the blank line before it ever reached layout — all are now `[^\S\r\n]{2,}` (identical behaviour on a caption with no newlines).

**White pill heading on wordier decks (2026-08-07).** `usesPillHeading(role, number, body)` in `layout.ts` — heading gets an opaque white plate + black text, no outline/shadow. **Derived, never stored**: role `reason` + numbered + has a body identifies exactly a wordier listicle, so no column, no migration, no API field, and short (1-3) decks stay untouched because they're unnumbered. It wins over the dark contrast plate. ⚠️ `lineBoxes` holds heading lines THEN body lines — the pill must `.slice(0, lines.length)` or it plates the body too and buries it.

**ONE LINE PER SLIDE, and it's enforced (2026-08-07).** The old rule said "short lines (most under ~12 words)", which bounds a LINE, not a caption — a strong model satisfies it by writing six of them. `viralExamples.ts` makes this worse in the right way: real decks stack short lines, so a model that actually follows its examples copies the SHAPE and returns six-line captions that bake as a wall of text (gpt-4o never did, so it never surfaced). Both copy prompts now demand ONE sentence, 6-12 words, no line breaks, and explicitly say the stacked examples are for VOICE not format. Backed by `overlongCaptions()` in `listicle.ts` (>14 words or any `\n`) wired into the existing retry loop in BOTH paths — mechanical, because prompt rules leak. Never truncates; the deck is rewritten with the offending slides named. `body` is exempt (short 1-3 slide decks use it as a paragraph by design).

**Captions are ALL LOWERCASE — the sentence-case rule was REVERSED (2026-08-07).** `cleanCaption` used to run `toSentenceCase`, added because the model "misread" sentence case and wrote all-lowercase. That had it backwards: the medium *is* lowercase (every deck in `viralExamples.ts`, and every caption transcribed off a live trending post — "whos ready for fall fits"), and the capital was silently undoing the voice the prompts spend thirty lines asking for — the prompt's own model answer `"i ate 180g of protein a day for 8 weeks"` came out as `"I ate 180g…"`. Now `toCasualCase` strips the sentence-initial capital instead, mechanically, for the same reason it was once added. Acronyms are safe (`(?![A-Z])` guard — "PSA"/"UK" survive) and mid-sentence capitals are untouched, so proper nouns inside a line keep their case.

⚠️ **String-concatenated prompts: a missing `+` does NOT fail the build.** JS automatic semicolon insertion ends the expression at the last operand and turns every following line into a dead expression statement — the prompt is silently TRUNCATED from that point, `tsc` passes, and nothing throws. Hit while editing `SYSTEM` on 2026-08-07. After editing any of these prompt blocks, verify every line but the last ends in `" +`.

**The copy model is swappable — `lib/generate/copyModel.ts` (2026-08-07).** ONE seam feeding both copy paths (`listicle.ts` stock + `imageFirst.ts` uploads), so an A/B is an env var, not a diff across the hard-won prompts — the thing under test is the model's VOICE, so everything else must stay byte-identical or the comparison is meaningless. `GEN_PROVIDER=xai` (or `grok`) switches to xAI, which is OpenAI-wire-compatible (same `openai` package, same `chat.completions.create`, just `baseURL: https://api.x.ai/v1`); `XAI_API_KEY` + optional `XAI_MODEL` (default `grok-4`). `OPENAI_COPY_MODEL` overrides the OpenAI-side model without touching the provider. **It never silently falls back** — `GEN_PROVIDER=xai` with no key throws a 400, because a silent fallback would make a misconfigured A/B look like a normal run and quietly measure the default (the exact shape of the `PEXELS_API_KEY`-local-only bug). The judge (`judge.ts`) and all image selection (`imageSelection.ts`, `liveImages.ts`) stay on OpenAI — deliberately out of the seam so only one variable moves. ⚠️ `imageFirst.ts` is a **vision** call and its failure mode is a SILENT fallback to copy-first + positional assignment; after pointing the flag at a new provider, check `04_*` in the diagnostics folder on the first upload run. Probe any provider before trusting it: `node scripts/check-copy-model.mjs <openai|xai> [model]` reports reachable model ids, whether **strict** `json_schema` works (`listicle.ts` depends on it), and whether vision is accepted.

**Requirements:** `PEXELS_API_KEY` must be set **in Vercel** (was local-only) for the live tier — without it, stock silently uses the old library.

**The hook is no longer forced to be numbered, and NUMBERING FOLLOWS THE HOOK (2026-08-07, Ernest).** `isValid` used to reject any 4+ deck whose hook lacked the digit, which is why every deck opened "N ways to…" — `hookBank.ts` ships six other shapes, injects them into every prompt, and the validator then threw away any hook that used one. **The model was never defaulting to lists; we were enforcing them.** Dropping that check alone barely moved the needle, because `normalize` still numbered every value slide and `layoutSlide` baked "1." onto each — a hook with no count reads as broken over a visibly numbered list. So `numbered` is now derived from the hook: `explicitListCount(hook) != null`. State a count and the slides are numbered to match; state none and nothing is numbered, which is what makes a curiosity gap / callout / before-after actually work. Measured after: **3 of 6 decks came back unnumbered**, and 0 self-numbered in the caption text (both prompts now tell the model not to write numbers itself). What still holds is CONSISTENCY — a hook claiming a count must claim the right one. ⚠️ Detection is a heuristic over `LIST_NOUNS`: it allows up to 3 words between the digit and the noun ("5 boring gut health fixes") and the noun list had to grow well past "ways/tips" — "fixes", "truths", "costs" all read as list counts and none were recognised. A count phrased with a noun outside that list just yields an unnumbered deck, which looks fine, so this fails soft.

⚠️ **`promptCount + 2` was a live bug** — that math assumed a CTA slide, so typing "3 exercises" built a 5-slide deck whose hook promised 4. Now `+ 1` (hook + N value slides).

**NO CTA SLIDE on a listicle (removed 2026-08-07, Ernest).** "follow for more X tips" as its own slide reads as corny and spends the slide people linger on longest on a request instead of a payoff — real decks don't do it (the reference gut-health post is a hook plus five numbered items and stops). 4+ decks are now `title + (count-1) reasons`, so the same slide count delivers one MORE item, and both copy prompts ban ending on follow/link-in-bio/save-this. ⚠️ **Short decks (≤ `SHORT_DECK_MAX`) are explicitly guarded** — their `"cta"` role is the PAYOFF slot, not a call to action (`shortDeckPlan`: "beat three — THE PAYOFF"), and only the role name is shared. Dropping the guard makes the prompt and the structure disagree about the last slide, so `isValid` fails and every short run burns a retry before `normalize()` forces roles back by position. `SlideRole` still permits `"cta"` so stored decks render. **Casualties to be aware of:** the composer Goal pill ("Grow followers") no longer has a slide to serve, and the product-link CTA that was built to NAME the product is gone — that was the conversion slide for Shopify sellers.

**NO plug/ad slide (removed 2026-07-19).** The structure used to force exactly one `plug` slide. With no product to sell the model filled that mandatory slot with junk — it parroted the user's prompt verbatim onto a random photo (proven across 3 diagnostic runs). Now every middle slide is a pure-value `reason`. `SlideRole` still *permits* `"plug"` so previously-stored slideshows keep rendering, but nothing generates it; `layout.ts` numbers it like a reason.

**The Goal pill was REMOVED (2026-08-07, Ernest).** It existed to steer the CTA slide's wording, so when the CTA went it became a second signal glued to the topic ("Goal of this post: Drive sales.") with nothing left to consume it — the exact shape of the drift bug the "prompt is the only subject" rule prevents. Gone from the composer, the mobile sheet, `/api/suggest`'s schema, and the AI-decide chips. ⚠️ `imageFirst.ts` was still instructing a **CTA slide that no longer exists** to serve the goal, so upload decks could reintroduce the follow-ask — removed with it. Two knock-ons: the product-link flow no longer nudges Goal to "Drive sales", and `/api/generate` keeps stripping a trailing "Goal of this post: …" because saved drafts still carry it. The onboarding profile's own `goal` is unrelated and untouched, including the `trends/remix` exception that deliberately reads it.

**Captions must NOT narrate the photo.** The old "captions GROUNDED in what the photos show" wording made the model label images — "mirror check-in:", "gym data:", "arm flex:". The caption carries the idea; the photo is only a backdrop it must be *compatible* with. Label-prefixes are explicitly banned in the prompt.

**Uploads never fall back to stock.** `imageFirst.ts` `normalize()` backfills any `photoIndex = -1` from unused uploads, so stock can only appear when uploads < slides. (The model used to over-exclude — 4 of 9 photos every run — leaving too few to fill the deck.)

## Trend blueprints — generation learns from the feed (2026-08-20)

Plain generations (no remix, no reference) are auto-steered by the strongest curated trend for the detected niche. `lib/generate/trendBlueprints.ts` picks the top-velocity `trending_posts` row that we *genuinely understand* — transcribed `slide_texts` (so the anatomy came off the real slides, not a hashtag description), a `hook_type`, ≥2 `anatomy` beats, and a hook that is real prose (`proseWordCount ≥ 3` — a live top post titled "SLIDESHOW IDEA!!" is what that gate exists for) — and rides it down the **same `format` channel remix and "Make one like this" already use**. No new model spend (curation already wrote hook_type/anatomy at ingest), one indexed SELECT + 5-min cache. An explicit client blueprint always wins; `"other"` niche gets nothing; any failure returns null and generation proceeds as before. Kill switch: `TREND_BLUEPRINTS=off` (default on). Side-by-side proof on "grow your arms": the steered deck carried rep ranges and named movements on every slide vs. generic advice without.

**Attribution lands with it**: every deck records `slideshows.gen_meta` (jsonb, migration `20260820120000` — **run it manually in Supabase**; inserts fall back without the column so deploy order doesn't matter): `{v, detail, compare, nicheSlug, formatSource: client|trend|null, blueprint: {postId, hookType, author, viewsPerHour}, model}`. This is the join key for the feedback loop (deck → tiktok_posts → scraped public views → which blueprints/hooks actually win), which is why it ships before the steering is proven — attribution is impossible retroactively. The scrape-back loop itself is parked until the Direct Post audit clears (needs public posts).

## Weak-prompt nudge — "Sharpen it" (2026-07-31)

A bare subject can only produce a forgettable deck. "cool cars" yields "vintage style meets modern design"; nobody acts on that. So when the composer prompt is a subject with no angle, we say so and offer sharper takes.

- **Detection is local, deterministic and free** — `assessPrompt()` in `lib/generate/promptStrength.ts` scores the prompt (+2 a number, +2 an angle cue like *how / truth / mistakes / best / vs*, +1 per length tier); `weak` is `score < 2`. It runs on every keystroke pause, so it must never cost a model call. Every string in `NICHE_SUGGESTIONS` scores strong; `"cool cars"`, `"my gym"`, `"our new espresso machine"` score weak. Empty is **not** weak — that's the Try pill's job.
- **`POST /api/sharpen`** (`gpt-4o-mini`, text-only, ~1s) returns 3 × `{prompt, why}` and **nothing else**. Deliberately not `/api/suggest`: that one also picks niche/slides/layout/goal, so adopting an idea from it would silently override settings the user already chose. Tapping a sharpened prompt changes only the text in the box. The route re-checks `assessPrompt` on the way in (so it can't be used as a general rewriter) and drops any rewrite that comes back still-weak.
- **The subject never changes** — same rule as the niche fix above. A sharpen of "cool cars" is three car angles, never a pivot to an adjacent topic or the creator's trade.
- **It is a nudge, never a gate.** Generate stays live the whole time. Collapsed it's one muted line under the box; the model is only called if the user taps "Sharpen it". Dismissal is keyed to the exact prompt text, so editing the idea brings it back but re-reading the same words doesn't nag. Hidden entirely in "Let AI decide" (the planner already pitches directions there).
- ⚠️ The stage is vertically centred, so `--arc-rise` on `/dashboard` has to clear the composer at its **tallest** — card + expanded panel + source switch — not just at rest. The panel growing is what pushed the horizon back through the source pills once already.

## Product link — Shopify / TikTok Shop sellers (2026-08-05)

Paste a store product URL and the deck is built from that product: its real photos, its price, its actual selling copy. Entry point is **"+ → Product link"** in the composer (a labelled section with its own input); pasting a URL into the idea box is a shortcut into the same section, so the product only ever appears in one place.

- **It is a READER, not a generator.** `POST /api/product` returns exactly the inputs `/api/generate` already takes — `userImages` + a topic `prompt` — so `listicle.ts` / `imageFirst.ts` / `/api/generate` are **untouched**, the same separation that protects the caption prompts from `/api/suggest`. Anything typed alongside the link rides along as the creator's own angle. Attaching a product moves the Goal pill to "Drive sales" **visibly** (only if still on the default), never silently.
- **The prompt is optional once a product resolves.** The brief IS the topic, so `genBlocked` drops the empty-box rule, the placeholder becomes "Optional — add an angle…" instead of animating topic ideas, and the "Try:" pill is hidden (its suggestions are subjects for a *different* post and would overwrite the box). Verified: empty box → a 3.5k-char prompt carrying the name, `$105`, the page's specs and the Drive-sales CTA, plus 5 product photos.
- **"Use our photos" means OUR photos, full stop.** On stock the product's images are dropped exactly like staged uploads are — `backgroundMode` stays `collection` and `userImages` is empty — while the product still drives the copy. An early version forced `backgroundMode: "single"` whenever a product had photos, silently overriding the user's source choice; that is the same class of bug as the old "stage photos in Stock mode and they force image-first". The chip says `using our photos` instead of a photo count, and the photo-supply warnings are suppressed. The `+` band therefore renders in **both** sources (Product link is about the product's copy as much as its pictures) with every photo affordance — Photos / Files / Collection, the counter, the hints, the file inputs — gated to Upload.
- ⚠️ **The niche is resolved in `/api/product`, from a SHORT topic line — never from the brief.** `/api/generate`'s `resolveNiche` keyword-vote is built for a sentence a human typed; against a 3.5k-char scraped brief a single incidental word decides everything. A deck for nic-free calming pouches hit `gym` on one "workout" buried in the page's marketing copy (tied with "tea"→cafe, and gym wins ties by being first in `KEYWORDS`), which loaded the **gym `pinterestPool`** — and because pool pins are deliberately ranked *before* Pexels and back-filled at random when no keyword matches, the judge approved candidate #0 on every slide: **6/6 slides were gym photos** under captions about kava and ashwagandha. `productTopicLine()` (title + type + vendor + the store's own one-line description) now feeds `resolveNiche`, and the slug rides through as an explicit `collection`, which always wins. Verified: pouches `gym → other` (pool returns `[]` for `"other"`, so pins vanish), sneakers → `fashion`. Re-run: **0/6 pins**, magnolia blossom under the magnolia-bark slide. Residual and expected: Pexels has no "nic-free pouch", so ~3/6 slides still log `NO CANDIDATE DEPICTS THE CAPTION → best-effort fallback` — topically right, not literal.
- **The CTA must NAME the product.** `listicle.ts` specifies the last slide as "a short, soft call to action (e.g. 'follow for more' or 'link in bio')", and that per-slide structure beats a mild request in the topic — decks were closing on "more about these in my bio", which wastes the one slide whose whole job is converting because the viewer never learns what to search for. The brief's closing block now hard-requires leading with the name, and supplies `shortName()` (strips pipes and parenthetical variant tails, prefixes the vendor when the title lacks it — "Calming Pouches (OTP)" → "Loosey Goosey Calming Pouches") plus the bare store domain. ⚠️ Price is passed through `ctaPrice()`, NOT `money()`: a `$15–$100` variant range came back on the slide as "**$15, $100**", so ranges are phrased "from $15" and the prompt says never to reword it. Result: `Loosey goosey calming pouches from $15 at looseygoosey.com`. (The lowercase brand is the existing no-Title-Case voice rule in `listicle.ts`, not a bug here.)
- **Three extraction tiers** (`lib/product/extract.ts`): Shopify's public `/products/<handle>.json` (no API key, ~110-280ms, most stores) → JSON-LD `Product` → OpenGraph. The product page **and the store homepage** are fetched in parallel with the API call and read for copy, because `body_html` is a poor description — measured from 1029 chars down to **zero** on live stores while the page carried full specs. On Allbirds that recovers `TENCEL™ Lyocell upper`, `Featherbed™ memory foam`, `Weight: 8.7oz`, `Stack Height: Heel 14mm` — exactly the concrete detail the virality model above demands.
- **`lib/product/pageText.ts` strips markup with a hand-written quote-aware scanner, NOT a regex.** `<[^>]+>` terminates at the first `>` even inside a quoted attribute, which Alpine/Vue themes have everywhere (`x-show="a > b"`); one such attribute desynchronizes the match and dumps raw JavaScript and class lists into the "copy" (`$store.cart.formatMoney` was landing in briefs). Logistics/error/newsletter sentences are filtered separately from UI chrome — "orders may take up to 30 days to ship" is grammatical, on-brand, and catastrophic on a slide.
- **Images are never guessed.** When a store publishes a gallery it is treated as authoritative and NOT supplemented from the page. Harvesting extra photos in put *other products* in the deck — five unrelated chocolate bars on Feastables, a backpack and a t-shirt on Death Wish. Two filtering heuristics were tried and each failed on a different store (long shared tokens match a BRAND; rarity-weighting inverts when one product dominates the page), so page-harvesting now runs **only** when there is no gallery (tier 2/3, e.g. Gymshark 403s tier 1 → 1 image → 6), gated on a ≥75% shared filename prefix. A thin gallery is reported honestly and stock fills the rest.
- **Product photos are pre-composed to exactly 1080x1920** (`lib/product/images.ts`) so the pipeline's `fit:"cover"` is a no-op. Packshots are square-ish (measured 0.84–1.09) and would lose ~44% per side. Alpha is flattened first (2 of 4 sampled were transparent PNGs → black silhouettes otherwise). Studio backdrops are detected by corner sampling and **extended seamlessly**; only genuine lifestyle shots get the blurred fill, because blurring a white packshot yields a grey slab that reads as a broken letterbox. ⚠️ sharp's `stats()` measures the **input**, ignoring pipeline ops — the crop must be materialized with `.toBuffer()` before measuring, the same gotcha documented in `contrast.ts`.
- **SSRF is the whole risk surface** — the URL is untrusted. https/http only, DNS-resolve-then-check (public names resolving to private space is the attack), every redirect hop re-validated, response size capped. Verified blocked: `localhost`, `127.0.0.1`, `169.254.169.254`, `10.x`, `file://`.
- **TikTok Shop and Kalodata cannot be read** and shouldn't be: both answer server-side fetchers with a bot wall (TikTok's captcha; Cloudflare `403 "Just a moment…"` for Kalodata). Kalodata is also a paid analytics SaaS whose product pages show *other sellers'* listings. Detected as `captcha` with an honest message. Real TikTok Shop support needs the official Partner API (seller OAuth) — separate project.

## TikTok reference — "Make one like this" (2026-08-09)

- **Resolving** (`lib/reference/tiktok.ts`, chain proven by `scripts/fetch-viral-example.mjs`): tikwm (free, keyless, handles vm.tiktok.com short links) → Apify ScrapTik (needs the aweme id, ~$0.002, shared trends budget). Fetching tiktok.com directly is impossible (bot wall). A video URL is a 400 with honest copy, not a silent fallback. **The reference's photos are analyzed and discarded — never stored, never rendered into the user's deck** (copyright).
- **Analysis** is ONE `gpt-4o` vision call (`detail:"low"`, ≤8 slides) → `{hookType, exemplarCaption: the transcribed hook, anatomy beats}`. The system prompt forbids subject words in beats — the anatomy must transfer to any topic ("lists a concrete protocol with sets and reps", never "talks about chest day").
- **Charged where the cost lives**: reserve 1 credit → resolve+analyze → refund on ANY failure. No client flag at generate time to trust or spoof. Admins bypass. Throttle 10/5min.
- **Composer**: paste a tiktok.com link in the idea box (`findProductUrl` now explicitly excludes TikTok hosts — the two paste flows can't collide) or the `+` menu → "Make one like this". **It is the ONE deliberately vibrant element in the composer** (gradient border/label — the visible price tag of the premium move; everything else stays muted, and that contrast is the design). The Slides pill visibly snaps to the reference's length (user can change it), the URL is stripped from the topic before generate, and the sharpen nudge hides while a reference is attached.

## Showcase format — product drops where photos carry the deck (2026-08-25)

Modeled on a real viral reference (Neboa matcha drop): hook + near-silent slides — slide 2 might say "i'm obsessed.", the rest say NOTHING. This is the photo_dump/product_promo mechanic `hookTaxonomy.ts` deliberately excludes from steering VALUE decks; for an announcement with real photos it IS the format, so it gets its own lane.

- **`lib/generate/showcase.ts`** — own vision prompt + own register: **exclamation marks and hype are ALLOWED here** (the value decks' lowercase-deadpan rules stay untouched — relaxing them inside the shared prompts would leak). Still no emoji (resvg tofu). One gpt-4o vision call: orders photos (best shot first), writes ONE hook (names product + place, 6-12 words), ≤2 fragments of ≤6 words, everything else empty text.
- **Auto-detected**: `detectShowcase(prompt, hasPhotos)` — uploads present AND the prompt reads as a drop/announcement (`DROP_CUES`: "new collection", "just dropped", "restock", "run to"…). A how-to prompt with uploads stays a value deck. Disabled in compare mode.
- **Caption placement flips**: hook rides `pos {y:0.2}` top-center (product shots are empty up top), fragments y 0.45 — carried per-slide via the same `pos` channel the judge's reposition op uses, so persistence/response needed no change.
- **What it skips**: trend blueprint (listicle anatomy would fight the silence) and the Supercharge judge (its rubric is the value doctrine; its favourite op would fill the silent slides). Falls back to the normal image-first path on ANY failure.
- `slideshows.layout` = `"showcase"` (column existed, unused); `gen_meta.format: "showcase"`; provenance strip explains the format. Empty captions render as zero lines (verified through composite).

## "Let AI decide" mode — the frictionless path (2026-07-21)

The composer's pill dropdowns are decisions to make *before* seeing anything. Most users are lazy and non-creative: they want to dump photos in and hit one button. The **"Let AI decide"** toggle (the pill that replaced "Help me find my hook") hides Slides/Layout/Goal entirely — only Source, an **optional** prompt, and the upload strip remain. (Niche is already gone from manual mode too — auto-detected server-side.)

- **It is a CONFIG PLANNER, not a second generator.** `app/api/suggest/route.ts` looks at the photos (+ optional direction) and returns ONE plan — `{niche, slides, layout, goal, angle, prompt, rationale}` — which is exactly the input shape `/api/generate` already takes. The user approves and the **unchanged** pipeline runs. **`lib/generate/{imageFirst,listicle,liveImages}.ts` and `/api/generate` are never touched by this feature** — that separation is the whole point, and it's what keeps the good caption prompts unbreakable. The planner is explicitly forbidden from writing slide captions.
- **Model:** `gpt-4o` **vision** when photos are present (it genuinely sees them — verified: 3 barber photos with no prompt → niche `beauty`, angle "inside a barber's daily routine"), `gpt-4o-mini` text-only for stock. Structured `json_schema` output, every field clamped/validated against the real enums so a bad model value can't poison `/api/generate`.
- **Suggestions are FREE but hard-capped at 3 per build** (`MAX_ROUNDS`/`MAX_SUGGESTIONS` = 3), enforced **both** client- and server-side (429 `suggest_cap`), plus a best-effort in-memory per-user throttle (~20 / 5 min). No credit charge, no fractional accounting, no schema change — only the final generation costs 1 credit. Refining passes `previous` so the model *adjusts* rather than restarting.
- **One-click approve is deliberate** — the AI can't mind-read, so it always shows a concrete plan you accept in one click or nudge in one line. There is intentionally **no** skip-to-generate bypass.
- Failure/timeout leaves a "Generate with defaults" escape hatch so users are never stuck; failed attempts don't consume a suggestion.

**Stock photos now disallows uploads entirely.** The attach button, counter and file inputs render only when Source = Upload, and card drag-drop is ignored on Stock — previously you could stage photos in Stock mode and they'd silently force the image-first path.

**Uploads are downscaled in the browser** (`downscaleImage`, 1280px long edge / JPEG 0.82) before hitting the wire — 10 full-res phone photos blew past Vercel's ~4.5MB body limit, and they now feed two endpoints.

## Generation robustness (2026-07-21)

- **Storage uploads retry.** `bad record mac` still occurs occasionally even with `agent:false` (so it's transient TLS/network flakiness, not session reuse). There was no retry, so one bad record threw away a whole generation. `uploadWithRetry` = 3 attempts, 300→600ms backoff, retries transport errors + 5xx/429, **fast-fails 4xx**. Never call `rawStorageUpload` directly.
- **No orphan rows.** The `slideshows` row is inserted before the uploads, so failures used to strand empty decks in the library (3 had piled up). Both the upload loop and the `slides` insert delete the row before rethrowing. Billing was already safe — `consume()` runs only after persistence.
- **NO EMOJIS, EVER — they physically cannot render.** `composite.ts` builds resvg with `loadSystemFonts:false` + only the TikTok Sans TTFs, which have no emoji glyphs, so an emoji bakes as a **tofu box ▯** (verified by rendering). Both copy prompts now ban them outright (they used to say "at most one emoji per slideshow"), and `stripEmoji` in `/api/generate` removes any that slip through. Digits survive (`Emoji` but not `Emoji_Presentation`).

## Performance — measure with `next start`, never `next dev`

**`next dev` timings are Turbopack compiling on demand, not real cost** (`/dashboard/analytics`: 994ms cold → 36ms warm). Always benchmark a production build before concluding anything. Supabase itself is healthy (~110ms auth, ~134ms PostgREST).

- **`proxy.ts` must NOT call `auth.getUser()`.** That's an unconditional network round-trip to `/auth/v1/user`, and the matcher covers nearly every path — it was charging **~110ms to every request in the app**, static pages and API calls included. It uses `getSession()` instead, which only hits the network when the token actually expired. Safe because the proxy makes no authz decisions ("no route guards" — every page/route calls `getUser()` itself).
- Results: `/privacy` 110→7ms, `/api/*` 115→3ms, `/dashboard` 366→251ms, `/dashboard/slideshows` 477→254ms.
- `getCachedUser()` (`utils/supabase/server.ts`) memoizes the user per request via React `cache()`. It did **not** improve latency — Next renders layout and page concurrently, so those calls already overlapped — but it halves auth API calls.
- ⚠️ `npm run build` starts with `rm -rf .next`; running it while `next dev` is live can corrupt Turbopack's cache. Stop the dev server first.

## Generation diagnostics — LOCAL ONLY (`lib/generate/diagnostics.ts`)

Every generation run dumps a full forensic folder so a bad slideshow can be diagnosed **without screenshots**:

```
diagnostics/Run_<N>_Diagnostics/          uploads (image-first) run
diagnostics/Run_<N>_Diagnostics_Stock/    stock (live Pexels) run
  00_SUMMARY.md   ← read first: request, auto-detected anomalies, caption→image map
  01_request.json / 01b_trend_exemplars.txt
  02_*_prompt.txt          EXACT system+user prompt sent to the model
  03_*_raw_response.json   raw model output, pre-normalization
  04_*                     per-slide image decisions (+ exclusions)
  uploads/upload_N.*       the user's photos, numbered as the model saw them
  images/slide_N_<role>.*  the final image used per slide
```

- Run numbers auto-increment across **both** kinds, so ordering is chronological.
- `00_SUMMARY.md` auto-flags anomalies: a plug slide parroting the prompt, reasons phrased as questions, title/prompt topic drift, and excluded uploads. **Read this before theorizing.**
- **Hard-gated to local dev**: returns `null` unless `NODE_ENV === "development"` AND neither `VERCEL` nor `VERCEL_ENV` is set — Vercel's FS is read-only outside `/tmp`, so dumps must never run there. All writes are `.catch(() => {})` so diagnostics can never break a generation.
- `/diagnostics/` is gitignored (so it's hidden in VS Code's explorer by default — open via `open diagnostics/Run_1_Diagnostics`).

**AI image generation is BACK (2026-08-25) as a third source.** (The 2026-07-17 MVP cut removed the old `gpt-image-1` fallback; Christian asked for its return.) `lib/generate/aiImages.ts` generates a bespoke portrait background per slide — composer sources are now **Upload** ↔ **Stock** (`#source-toggle`, unchanged for e2e) plus an **"AI images"** switch (`#ai-images-toggle`, `backgroundMode: "ai"`). Model/quality are env knobs: `AI_IMAGE_MODEL` (default `gpt-image-2`) + `AI_IMAGE_QUALITY` (**default `low` — the only tier the surcharge prices; repricing in `costOf()` is REQUIRED before raising it**). Prices per portrait 1024×1536 image (verified 2026-08-25): gpt-image-2 $0.005/$0.041/$0.165 (low/med/high), gpt-image-1-mini ~$0.006/$0.015/~$0.052, gpt-image-1 (deprecates 2026-10-23) $0.016/$0.063/$0.25. **Billed +1 credit per block of 5 slides per deck** — worst path (10 slides = 2 credits = $0.50 vs $0.05 inference) sits exactly at the 90% floor. Failed slides fall back to the stock pipeline per slide; ALL slides failing aborts with `ai_images_unavailable` + full refund, never a stock deck at AI price. `gen_meta.aiImages` records model+quality; admin cost dashboard tracks it as `aiImages`. Probe: `node --env-file=.env.local scripts/probe-ai-images.mjs` renders one test image per candidate tier into `diagnostics/ai-image-probe/`.

**AI replacement for judge-rejected STOCK slides (2026-08-27).** On the pure-stock flow, a judge `-1` (no candidate clearly depicts the caption — see the two-pass strict judge above) gets a bespoke AI background (`generateOne` via the same worker pool) instead of the closest non-match. **Cap** (`aiFillMaxPerDeck()` in `route.ts`): **uncapped in local dev** (testing shows the feature at full strength; with the strict judge ~4/6 slides of a real deck can reject), **3/deck in production** (~1.5¢ at gpt-image-2 low — absorbed as a quality cost, NOT priced), `AI_STOCK_FALLBACK_MAX` overrides either. Raising the prod cap or quality tier requires a `costOf()` surcharge per the margin doctrine — with strict judging the prod cap is the known gap: slides rejected past 3 still get best-effort stock. Only fires on the main stock call — never on AI-mode gap-fill (AI already failed those slides) or the Supercharge judge's resource ops. Any failed generation falls back to the old best-effort Pexels chain, so the path can only improve a slide. Kill switch `AI_STOCK_FALLBACK=off`; provenance in `gen_meta.aiFallback` `{model, quality, rejected, filled}` + diagnostics `04c_ai_stock_fallback.json`. Caveat: product-link decks name real products, where image models hallucinate most visibly — if that bites, gate on the deck not being product-sourced.

## Billing — Stripe LIVE (multi-tier + credits)

`lib/billing/` — multi-tier subscriptions (Growth $19 / Scale $29 / Unlimited $79, fair-use ceiling) + one-time credit packs, on the `profiles` table (**service-role-write only** — entitlements must NOT live in `user_metadata`, which the browser can edit). Hard monthly-quota + per-user generate rate-limit enforcement in `/api/generate`. `app/api/stripe/{checkout,webhook,portal}`; `components/dashboard/BillingModal.tsx`. Env: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (prod differs from the local `stripe listen` one), `STRIPE_PRICES` (one JSON blob mapping ids → Stripe price ids). Migrations `20260707180000_billing.sql` + `20260713190000_billing_tiers.sql` + `20260714120000_generation_rate_limit.sql` + `20260806130000_billing_atomic.sql` + `20260810000000_profiles_selfheal.sql`.

**MARGIN DOCTRINE — inference margin is AT LEAST 90%, bare minimum (Ernest, 2026-08-09).** Every PRICED operation must clear a 90% gross margin on its model/API cost against the medium credit-pack rate (**$0.25/credit**), on its WORST path, not its typical one — and blended subscription margin must sit ≥90% at expected utilization. When an op can't clear the bar, raise its credit price or cut its cost; never ship it under the floor. Known tension to resolve in the pricing-ladder rework (LAUNCH_TODO §5): base generation's worst path (~5¢) is ~80–86% against packs — the levers are OpenAI prompt caching (the voice corpus + exemplar blocks are static per niche; caching halves copy input cost) and trimming Scale's 400 quota (at full use Scale yields $0.0725/credit, where NO op clears 90).

**Credit price list (repriced 2026-08-09, second pass: EVERY model call is priced — Ernest's rule; `costOf()` is the single source of truth for generation).** Generation **1**/slideshow (×N for the 2-versions toggle); **Supercharge ×3** (raised from ×2 — worst path gpt-4.1 judge + full regenerate ≈10¢ was an 80% margin at 2); **TikTok reference ("Make one like this") 2**, charged in `/api/reference` (~1¢ → 98%); **AI image swap 1 per block of 3 per deck** (upload swaps free — no model call); **AI-generated backgrounds 1 per block of 5 slides per deck** (gpt-image-2 low, see the AI-images section); **Let AI decide 1 per planning call** (gpt-4o vision, up to 3 rounds/build → worst 3 credits + the generate); **Sharpen 1**; **Remix 1**. All charged reserve → run → **refund on failure** in their own routes, admins bypass. Zero-inference actions (editor ops, upload swap, product-link read — scraping + keyword vote, no model) remain unpriced: charging non-inference earns nothing and punishes users. Trend ingest + slide-text transcription are a FIXED ~$35/mo platform cron, not attributable per user — if ever monetized, gate the Trends tab to paid tiers, not credits. Throttles (per user, rolling 5-min): suggest 20, sharpen 30, product 30, remix 30, image-route 40, reference 10.

**Billing is ATOMIC, in Postgres (2026-08-06) — never reintroduce a JS check-then-write.** `spend_credits` / `refund_credits` / `claim_generation_slot` / `claim_rate_window` / `bump_image_swaps` are `SECURITY DEFINER` RPCs (row locks / compare-and-swap), because the old read-modify-write let N parallel requests get N decks for one charge. Flow is **reserve → run → refund on failure**, and the reservation carries the allowance/credits split so refunds restore the right bucket. `/api/generate` requires auth (the old guest-preview branch was an open spend endpoint reachable only by curl — deleted).

**Guards return `GuardResult`, and infrastructure failure ≠ policy denial (2026-08-09).** A guard that ERRORS (RPC missing, DB down) returns `{reason:"error"}` → 500 `billing_unavailable` with the Postgres error logged and echoed as `detail`; only a genuine `{reason:"denied"}` gets the 429/402 copy. The old boolean collapse reported a dead RPC as "You're generating too fast", which sent a real user chasing a rate limit that never existed. Fail-closed is unchanged — an errored guard still blocks and charges nothing.

**A `profiles` row is NEVER assumed (2026-08-09).** Six real users had no row (the signup trigger had silently missed them; `loadBilling()`'s lazy upsert used to paper over it and the hardening pass removed loadBilling) — and every guard read "no row" as a denial, permanently locking them out with a rate-limit message. `20260810000000_profiles_selfheal.sql`: backfills, makes the trigger idempotent and unable to fail a signup, and calls `ensure_profile()` at the top of all three guards. Standing invariant: `select count(*) from auth.users u left join profiles p on p.id=u.id where p.id is null` must be 0. ⚠️ Admin accounts (`lib/admins.ts`) bypass every guard — so founder testing can NEVER reproduce a billing-gate bug; test with a non-admin account.
